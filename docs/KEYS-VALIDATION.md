## 环境与测试命令

- Windows x64；Node 22.22.3（库/桌面）、Node 20.20.2（两站）；Electron 44.3.0；共享库、桌面均为 0.6.1。
- 两站用同一新版 tgz，178 个已安装 `dist` 文件逐字节一致。UliUli 的 `codex/windchime-desktop-v0.6.0` 和 Mia 的 `codex/live-broadcast` 保持原分支。
- 独立生产构建目录 `.windchime-key-test`。UliUli BUILD_ID `AOskjk1t1t9RtrrQtjGHC`；Mia `h11MwdTJhUoU41vYfD787`。两站构建 exit 0，各有一项原有 Next 文件追踪范围警告，无编译错误。
- 测试服务器 `http://127.0.0.1:3031` 和 `http://127.0.0.1:3032`；数据库、图片、密码、盐和会话均为隔离合成配置，没有读写真实信件和平台密钥。
- 测试使用临时 SQLite、临时 Windows 用户数据目录、同一浏览器的两站登录以及两个独立 Electron 主进程。不启动接入网关，不部署生产。

```powershell
# WindChime 根目录
npm test
npm run typecheck

# apps/desktop
npm test
$env:WINDCHIME_SMOKE_ALLOW_WRITES='1'
$env:WINDCHIME_SMOKE_PASSWORD='<隔离测试站的管理员密码>'
$env:WINDCHIME_SMOKE_ULIULI_ORIGIN='http://127.0.0.1:3031'
$env:WINDCHIME_SMOKE_MIA_ORIGIN='http://127.0.0.1:3032'
npm run test:keys
npm run test:smoke
npm run make
```

`test:keys` 会输出四个合成话题和一个仅监听 loopback 的临时夹具接口。通过真实网页登录，在每个话题填写名称并点击生成密钥；由浏览器验证程序读取生成字段，将密钥直接传入该接口的内存，再通过 IPC 送入两个桌面实例。密钥不出现在进程参数、测试日志和报告中。桌面真实 React 输入框及连接按钮调用打包的 preload/main 导入流程。最后须在网页点击撤销共享密钥，脚本才会完成；详见 [桌面 README](../apps/desktop/README.md)。

## 修复与失败记录

- 代码审查发现导入先切换、后保存，可能在磁盘失败时改变旧连接。改为先加密并原子保存候选，再提交内存和安全切换；补充实际加密、写入、重命名失败和异步选择测试。
- 远端错误的 `code` 也可能携带敏感内容，导入失败仅返回本地白名单错误码。
- 慢导入成功时，仅清空这次提交的密钥文本，保留用户期间新粘贴的输入。
- 首次网页测试混用了 `localhost` 配置与 `127.0.0.1` 地址，正确收到来源拒绝；统一测试来源后重新运行。
- 浏览器程序曾在话题异步切换结束前填写名称，输入随话题重挂被清空；修正为等待目标话题就绪。没有跳过服务端来源校验。
- `x8qcuQ` 轮测试脚本尚未选中来信就等待编辑器，失败；`Qd4dkJ` 轮等待正在关闭的旧 renderer 的 JS 响应超时。修正测试观察逻辑：先选择来信、给观察请求设时限、等待旧原生窗口真正关闭，未知状态不作为空白通过。随后 `oGrTJG` 四话题全流程通过。未把前两轮计为通过。
