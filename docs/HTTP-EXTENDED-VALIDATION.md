- 运行客户端：Windows，Node `v22.22.3`。

- 两站 capabilities 均声明协议 1、图片/配对/直播能力、1000 ms 轮询、3000 ms 租约。两个持久 `siteId` 不同。
- 未重启服务、未控制浏览器、未读取生产密钥、未改变默认话题/全局设置/其他已有信件。脚本使用新的 UUID 合成话题与信件；收尾仅结束自身话题并撤销自身授权。合成信件保留，便于后续人工复核。
- 不复跑已通过的基础 50 项 HTTP 测试与迁移测试。本轮也没有修改共享库源代码或两站实现，因此不需要重新打包或部署。

在 WindChime 目录，沿用本地隔离站点的测试密码：

```powershell
$env:WINDCHIME_SMOKE_ALLOW_WRITES = '1'
$env:WINDCHIME_SMOKE_URLS = 'http://localhost:3011,http://localhost:3012'
$env:WINDCHIME_SMOKE_PASSWORD = '<本地隔离站点测试密码>'
node --check scripts/test-live-http-extended.mjs
node scripts/test-live-http-extended.mjs
```

最终联合执行退出码 **0**，输出 **335 项主流程断言通过**，约 8.6 秒。该数字包含 HTTP 状态断言及业务数据断言，不代表 335 个独立场景；最后的结束展示与撤销授权请求也全部成功。

最初两次是新测试脚本自身的契约校准：无效图片收据实际为 `409 INVALID_RECEIPT`；公开投稿成功响应不包含私有信件 ID，需由管理接口取得。这两次不计入通过结果，均已执行自身授权的撤销/结束清理；没有为适配测试更改服务端行为。

| 实际验证 | 观察结果 |
| --- | --- |
| 站点间令牌互换 | A 站签发的有效展示/管理令牌在 B 站返回 401，反向同样拒绝 |
| 话题管理范围 | 管理令牌读取另一话题、为另一话题签发授权返回 403；同话题命令指向另一话题信件返回 404 |
| 展示只读边界 | 展示令牌读取完整信箱、管理状态、私有图片、执行隐藏或签发管理授权均拒绝；同时附加管理员密码请求头也不能把错误类型令牌升级 |
| 接收器范围 | 不同话题展示令牌与接收器交换组合返回 409 |
| CORS 与后台授权 | 独立展示 Origin 携带管理员凭据读取控制状态返回 403，响应不含 `Access-Control-Allow-Credentials` |
| 图片上传收据 | 跨话题消费及二次消费均为 409；错误尝试没有消费合法话题的首次收据 |
| 图片规范化与预览 | 上传 12×9 PNG 后得到 12×9 WebP；私人预览与当前展示文件的 SHA-256 都与服务端确认值一致 |
| 仅当前图片 | 审核后尚未手动上屏时不可取图；播 A 时不可取 B 图；切到 B 后，无论拿旧 activation 或当前 activation 均不能读取 A 图；隐藏后不可读取 B 图 |
| 展示数据投影 | frame 只包含当前快照图片，未包含待审信和其他话题信件；图片响应 `Cache-Control: no-store` |
| 旧状态不等于批准 | 通过旧 API 设置已读、收藏、取消敏感词标记后，信件仍为 pending，输出为空白 |
| 并发控制版本 | 同一 revision 同时提交两个外观操作，结果恰好为 200/409，失败码 `REVISION_CONFLICT`，版本只递增一次 |
| 迟到命令重放 | 手动上屏后隐藏，再重放完全相同的旧 show/operationId，输出仍为空白 |
| 断线与重新连接 | 停止轮询 3250 ms 后旧接收器返回 `409 RECEIVER_EXPIRED`；控制状态不再声称正在展示；新 open 为空白且旧图片不可访问 |
| 批准、顺序与阅读状态 | 顺序调整为 B/A；结束展示并重新 open 后顺序、批准、已读、收藏均保留，内容不恢复 |
| 旧后台变更联动 | 标记敏感、删除当前信件、归档正在展示的话题都立即在下一次服务读取中撤下；取消敏感标记后仍需重新批准 |
| 管理设备撤销 | 管理令牌派生的展示授权在撤销父授权后返回 401；另一份独立展示授权仍可读取当前获准快照 |
