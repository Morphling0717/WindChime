## main 到开发分支审查

- **认证与范围：**两站原 Cookie 登录和历史密码认证仍由各自 `mail-auth` 适配器处理。新增 live 路由转给共享处理器；网站登录可以签发站点控制密钥，已有控制密钥不能签发另一个管理密钥。展示 Bearer 即使同时携带管理员 Cookie 也不能进入管理接口。实际 HTTP 测试验证跨来源 Cookie 的密钥签发被拒绝，以及两站 Bearer / Cookie 不能互用。
- **Mia 迁入共享服务：**主分支里的邮件 SQL 已由共享服务接管，原邮件路由保留 HTTP 方法并转给共享处理器。`dbReady` 等待共享迁移与宿主建表，公共话题页面只使用公共 DTO。默认数据库路径保留 `codes.db`，UliUli 保留 `data/codes.db`；两站哈希盐继续用 `??` 和原站点默认值，因此显式空字符串没有被替换。
- **迁移与历史状态：**新增结构和触发器由共享迁移执行。每站 fresh / legacy / current 三组隔离样本各运行两次迁移，检查 SQLite integrity、原信 ID/正文/时间/已读/收藏/发送者哈希、活动备注/归档、黑名单、宿主哨兵数据以及授权 hash/到期/撤销/父子关系。旧密钥保留 topic 范围；现有 site 密钥不被降级或借用默认话题。
- **原有功能：**两站 `scripts/test-mail.mjs` 使用各站真正的登录路由获得 Cookie，覆盖投稿、公开 DTO/SSR 隐私、话题隔离、收件箱筛选、收藏、归档恢复、旧审核、批量操作、拉黑/解除与设置。UliUli 原表单和 Mia 发送组件均把上传收据交给共享投稿接口。本次没有替换网站 UI。
- **密钥与编辑状态：**网页密钥组件以 topicId 为 React key，切换话题会卸载旧显示；退出登录先清除认证 UI。编辑话题弹窗的初始化与打开/话题切换绑定，轮询不会反复覆盖正在编辑的字段。词库 UI 根据网站设置显示，网页没有新增开启开关。
- **路由/PWA：**`/mail/live` 只向 `/mail` 保留经过长度限制的 topicId / userCode / deviceCode，不传任意 token 参数。Service Worker 在处理导航/缓存前排除 `/api/`、`/mail`、`/live`。通过本地实际提供的 sw.js 在 VM 中执行 fetch handler，确认这些请求没有调用 respondWith。此项只验证分支行为，不宣称真实浏览器离线缓存已经验收。

在上述审查与实测范围内，未确认新增阻断问题。这不是对未执行功能的无缺陷保证。
