# Windows 桌面验证记录

> **历史验收记录。** 下文保留当时版本、范围和实际结果；其中的「本轮」均指该次历史验证。本轮独立桌面窗口版的当前证据见 [DESKTOP-LOCAL-VALIDATION.md](../../docs/DESKTOP-LOCAL-VALIDATION.md)。旧平台相关结果或待办不作为当前本地桌面流程的前置条件。

验证日期：2026-09-10、2026-09-11。环境：Windows 11 Home Single Language 25H2，64 位，10.0.26200.9168。Electron 44.3.0、Electron Forge 7.11.2。验证仅使用一次性本机 fixture 和两站专用验收数据库，没有读取或改变生产信件，也没有使用真实 B 站平台密钥。

## 已通过

- 桌面与根库 TypeScript 检查通过。
- `npm test`：9 项主进程安全边界和竞态测试通过，覆盖地址、IPC 路由／信箱范围、配对材料、启动参数、新配对切换、旧窗口回调、旧请求及平台租约错误、旧写请求之后再隐藏。
- `npm run test:smoke`：真实 Electron 主进程、私人窗口与独立展示窗口运行，12 项检查通过，控制台错误 0。报告：`out/smoke/report.json`；截图：`out/smoke/control.png` 与 `display.png`。
- Electron 流程验证：私人原文可见、配对秘密不进入 renderer、显示与控制 preload 分离、跨信箱拒绝、普通 IPC 不能创建授权、首次空白、批准不自动播出、手动上屏、原始未审核正文不出现在输出、撤销立即撤下、重载需重新上屏、断线清空。
- 展示截图用 RGBA 像素检查，透明区域 alpha 为 0。这不是实际直播软件采集测试。
- `npm run make` 实际生成 Windows x64 Squirrel 安装程序、ZIP、RELEASES 和 nupkg。打包运行文件使用白名单，不包含源站环境文件、平台密钥、测试 fixture 或签名证书。
- 本机先确认不存在同名已安装程序和用户数据后，实际执行测试包静默安装，退出码 0；安装后启动已安装的 `WindChime.exe`，通过 Windows UIA 核对私人首启界面，连接列表为空，未恢复或自动打开展示窗口。再次启动由单实例机制处理。

共享接收器／组件测试位于仓库 `tests/broadcast-receiver.test.mjs` 和 `tests/broadcast-ui.test.mjs`，最终构建的 11 项测试全部通过。除租约、迟到响应／图片、撤销、重启外，还验证远端编辑保留本地未保存草稿、中文链接与空白规范化保存不产生假冲突、保存期间继续输入不丢失、较新的远端版本不被旧响应覆盖，以及替换 display client 时同步返回空白。后者在旧构建上实际复现了旧信箱快照被新 client 的 render 回调接收，修复为按 client 身份过滤 React state。

## 卸载发现与修复范围

首次执行 `Update.exe --uninstall --silent` 返回 0，并移除了桌面／开始菜单快捷方式，但正在托盘运行的程序进程未退出，导致程序文件仍被占用。停止本次新安装的测试进程后，再次卸载将程序可执行文件移除，没有遗留 WindChime 运行进程；测试安装目录保留 `.dead` 标记、Update.exe 和部分目录。没有删除或修改已有用户应用。

源码已修复：Squirrel 卸载启动会通知运行中的单实例退出，运行实例结束展示并退出；卸载处理等待文件释放。修复已进入最终安装包，但修复后的真实安装／卸载往返尚未复验。

自动审批拒绝了“清理本次测试残留的安装目录，然后重新安装最终包”的命令，只返回 `blocked by policy`，未说明更具体原因。被拒绝的命令未执行，也未改用其他方法绕过。此项不能标记为通过。

## 2026-09-11 两站真实适配器与重启

使用用户已启动的 UliUli 3011、Mia 3012，数据位于专用 `.work/runtime/uliuli.db` 与 `mia.db`。每站新增两个唯一合成话题，各两封合成来信。实际 Electron 使用临时 `userData`，主进程生成 PKCE 校验材料、请求设备码；浏览器逐一核对四个配对 URL 的话题与配对码后明确批准。控制 token 只进入主进程与系统加密 vault，未放入 renderer 或报告。

四个话题均通过：原始来信仅私人可见、网页管理员 API 修改并批准后桌面同步但输出空白、桌面手动上屏、已读／收藏及顺序回写、网页 API 撤销撤下、修改需要重新批准、新配对完成立即关闭旧输出、跨站显式切换保持空白。网页批准通过真实页面执行；之后的“网页侧”操作通过网站自身管理员 HTTP 接口执行，与桌面 IPC 构成双向同步验证，不冒充逐个网页按钮测试。

真实退出第一 Electron 进程后，以同一临时目录启动独立的新进程，四条加密授权与选中连接读回，待播批准与顺序保留，启动没有展示窗口。重启验证额外使用独立只读接收器维持一个当前播放的信，再打开展示窗口仍空白；主播式手动上屏后显示，网页 API 隐藏后清空。测试结束已撤销本次所有设备与展示授权，合成话题保留供复核。

第一次重启测试脚本错误地要求 `control/state.current` 在旧接收器退出后始终非空，触发 TypeError；服务端会按在线接收器返回 current，属于测试前提错误。已改为上述独立 observer 场景，重新启动的验证进程全部通过。报告为 `out/site-smoke/first-report.json`、`restart-report.json`；原始报告目录 `C:/Users/ASUS/AppData/Local/Temp/windchime-site-smoke-5nmNbd`。修正后的完整脚本可用 `npm run test:sites` 重复执行。
