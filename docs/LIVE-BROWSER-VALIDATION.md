## 两站均通过的基础流程

1. 按原方式登录网站，进入私人 `/mail/live`。
2. 新合成信未审核时展示页空白；批准进入待播后仍空白。
3. 审阅并手动展示后的正文、昵称、两张规范化图片和图片说明出现在独立展示页。
4. 手动切换下一封；队列末尾转为空白，已批准列表和顺序保留。
5. 刷新展示页后先空白；确认新的 `display/open` 已完成后，手动上屏成功。
6. 撤销当前信件批准，展示撤下；结束展示后批准列表/顺序保留。

独立展示页实际背景透明，无 Service Worker，无收件箱 API 请求，无私人控制元素。已观察到的展示业务请求限于展示连接、frame 和当前图片读取，不包含完整收件箱。它与登录、审核、设置所在页面分离。

## 隐藏延迟

本次计时起点为隐藏请求成功响应，终点为展示 DOM 撤下；每站 8 次。单位均为毫秒。

| 站点 | 逐次实测 | 范围 | 中位数 |
| --- | --- | --- | --- |
| UliUli | 922.0、697.8、462.4、745.3、498.3、778.6、545.8、839.2 | 462.4–922.0 | 721.55 |
| Mia | 697.1、506.1、802.5、579.3、898.6、704.6、473.4、778.1 | 473.4–898.6 | 700.85 |

16 次本机样本均小于 1000 ms。此结果不构成对其他网络、设备或浏览器负载的延迟保证。早期 1490 ms 观察从自动化点击调用开始计时，包含定位、滚动和等待，测量口径不同，未混入此表。

## 测试脚本与产品问题的区分

- 自动化最初用精确 label 定位 textarea 失败，改为匹配当前实际 label 后继续。这是测试定位调整。
- 重连测试最初只等待旧的在线接收器计数，便发出 show；新展示接收器随后才 open，因此按安全规则不恢复旧激活内容。改为等待本次新的 `display/open` 完成后再手动 show，两站通过。这是测试前提修正，没有放宽服务端启动空白规则。
- 旧展示脚本刷新后丢失 fragment 中的只读重连参数是产品问题，已经修复；本报告的刷新后手动上屏流程已复验通过。真实 H5 容器不是本次浏览器验收对象。
- 中文链接/空白规范化后保存成功却误报远端冲突是后续发现的产品问题：旧 UI 以 JSON 字面相等判断是否自己的保存，不能识别服务端 URL 编码和裁剪。现已使用该次 action 的确切响应及提交版本 +1 更新编辑基准，保护保存期间的新输入和真实远端冲突。`npm run build`、`npm run typecheck` 与 UI 6/6、共享接收器/UI 11/11 通过；**这项最新修复尚未在两站重启后的浏览器中复验**。
