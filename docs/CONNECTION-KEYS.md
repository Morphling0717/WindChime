# 桌面连接密钥与 0.6.1 升级

连接密钥用于将风铃桌面控制端连接到网站中的一个话题。网页与桌面继续共用网站服务端的收件箱、审核、待播排序和上屏状态；展示窗口始终使用独立只读授权。

## 先升级网站

网站必须安装并实际运行 `@windchime/embed` 0.6.1，桌面应用也使用 0.6.1。旧站点没有新接口；仅更新安装包、修改仓库依赖或打开新网页标签，不会替换正在运行的旧服务。

尚未公开发布到 npm 时，在 WindChime 仓库构建 `windchime-embed-0.6.1.tgz`，由网站固定安装同一文件并提交其 `package.json`、lockfile 和 vendor 校验记录。UliUli 与 Mia 的接入步骤见各站 `docs/WINDCHIME-LIVE.md`。本轮没有部署生产站点，也没有读取或改动真实平台密钥、生产数据库和匿名身份盐。

升级前保留原数据库、私有图片目录、配置和旧版本代码的可恢复备份。先用数据库副本完成初始化或迁移、构建和回归，再安排站点的实际部署。继续保留 `DATABASE_PATH` 与 `WINDCHIME_HASH_SALT` 的原值；已存在的信件、话题、审核记录和设备配对不需要为密钥功能重新创建。

0.6.0 → 0.6.1 的连接密钥功能复用现有控制授权表，不新增数据表或列。更早版本仍按 [MIGRATION.md](MIGRATION.md) 完成原有初始化和迁移。

## 生成和导入

1. 使用网站原有登录方式进入 `/mail/live`，选择要连接的话题。
2. 在连接授权区域生成桌面连接密钥，核对话题和到期时间，并复制完整密钥。
3. 在桌面连接界面粘贴密钥并导入。桌面验证站点和授权成功后，保存加密的本地连接信息；管理员登录密码只用于网站。
4. 打开独立展示窗口，再按“审阅 → 批准 → 手动上屏”操作。生成或导入密钥、打开窗口都不会自动播出信件。

完整密钥只在创建时提供。授权列表只显示名称、所属话题、到期和撤销状态；丢失密钥后可以生成新的授权。不要将密钥放入公开链接、直播画面、日志或仓库。

密钥自生成时起有效 **30 天**，在到期前可以重复导入；重复使用不会延长到期时间。关闭桌面或重启电脑不会消耗密钥，也不会自动恢复上一次展示的信件。

密钥以 `wc_conn_v1.` 开头，包含网站地址、站点标识和控制令牌；其编码不是加密。桌面先检查网站声明的 `connectionKeys` 能力，再通过只返回授权元数据的 `/control/identity` 核对真实站点和话题。公开站点使用 HTTPS，本机测试可使用 `localhost`、`127.0.0.1` 或 `[::1]` 的 HTTP 地址。

## 多台电脑与撤销

同一密钥可以在多台电脑导入。这些电脑共享同一个话题授权，在网页和桌面上进行的审核、排序、显示与隐藏操作会作用于同一份服务端状态。

在网站撤销该密钥后，所有使用它的电脑连接都会失效，由它签发的展示授权也随之失效，当前输出必须撤下。需要分别撤销不同电脑时，应在网站为每台电脑生成独立密钥，并使用便于辨认的名称。

更换密钥时，先生成并导入新密钥，确认话题无误，再撤销旧密钥。撤销不会删除信件、话题或已批准的待播列表。到期后需要生成新密钥；持有旧密钥不能自行续期或改变话题范围。

连接密钥包含审信和播出控制权限，只交给需要管理该话题的人。直播软件仍只采集 **WindChime Display** 窗口，并使用严格标题匹配；观众展示页和展示凭据无法读取完整收件箱或执行管理操作。

## 旧浏览器配对作为备用

桌面保留原有浏览器配对入口：填写网站地址，在打开的私人页面核对配对码并批准话题，然后回到桌面完成连接。该配对码有效期为 10 分钟且只能完成一次；获得的设备授权沿用原有到期和撤销规则。

在尚未部署 0.6.1 的 0.6.0 站点上，可以继续使用旧配对。若新密钥导入提示网站不支持，请先确认线上站点版本，不要使用管理员密码或只读展示链接代替连接密钥。

## 运行和验证

桌面开发运行、Windows 打包与独立窗口采集方式见 [apps/desktop/README.md](../apps/desktop/README.md)。独立桌面流程不依赖 B 站网关、平台密钥、H5 或上架审核；这些可选接入维持单独配置。

本轮实际测试、隔离环境和仍未完成的项目由 [KEYS-VALIDATION.md](KEYS-VALIDATION.md) 记录。旧 [DESKTOP-LOCAL-VALIDATION.md](DESKTOP-LOCAL-VALIDATION.md) 保留 0.6.0 的历史结果，不作为 0.6.1 新接口已通过测试或已上线的证明。
