## 已定位并修复的问题

1. **中文安装路径导致快捷方式创建失败。** 已发布 0.8.2 EXE 在新的隔离目录实际首次安装时出现调用异常。复现确定旧 WScript.Shell 迟绑定路径会发生 ANSI 转换，中文变为问号。改用明确的 IShellLinkW / IPersistFile Unicode 接口，保留快捷方式名称、工作目录、说明和安装事务。错误界面展开内部异常，显示实际失败原因。玻璃向导、Logo、MIT、目录和快捷方式选项均保留。
2. **快速连续更换“下一封”热键可能遗留旧注册。** 两次保存交错会各自读取过时状态；改为顺序完成注册、持久化、注销和失败回滚，录制不能穿插保存过程。
3. **热键保存失败后，磁贴保存可能把失败的值写回文件。** 临时热键不再提前写入共享配置；原子提交成功才更新已提交值，磁贴保存读取当时的已提交配置。补充同时保存、写入故障和重启回读回归。
4. **新热键还没保存成功就能触发下一封。** 现在只先预留系统组合键，回调必须确认它已成功提交才执行。保存期间原热键继续可用；失败的新热键不能播出。

快捷方式回归使用真实 .NET Framework / COM，在临时目录验证中文目标、名称、工作目录、说明及读取，8 项通过。实际调用线程分别设置并断言 en-MY / zh-CN 和 STA / MTA，包括 Task.Run 内的地区与线程断言。不改用户快捷方式，**不能代替最终 EXE 安装**。

Windows CI 首次运行另暴露三条测试路径断言不兼容 RUNNER~1 短路径。仅将新建测试目录通过 fs.realpath 规范化，保留路径安全断言；真实 DOS 短路径回归 11/11 通过，后续 Windows CI 通过。失败证据保留。

## 候选与命令

最终后台候选提交、构建环境、EXE／ZIP 摘要和包检查结果记录在 [candidate-report.json](evidence/0.8.3/candidate-report.json)。其中“通过”只对应明确列出的后台检查，不代表前台成品门槛通过。

旧 005312e 候选已经由后续热键修复取代，不得发布。它的暂存核验、管理 UI 验证和失败截图保留历史标记，不能算作最新候选验收。新的包从独立 Git worktree 和独立 npm ci 依赖生成，不覆盖仍打开在欢迎页的旧测试 EXE。

构建和验证命令：

- 共享库：npm test；npm run pack:check。
- 独立 worktree：根目录和 apps/desktop 分别 npm ci --no-audit --no-fund。
- 桌面：npm test；npm run make。
- 独立目录的包校验前运行 node node_modules/electron/install.js，准备锁定版本的官方 Electron 发行文件作许可比对；该命令只下载／解包，不启动应用。当前 Electron 包不会通过 npm ci 自动准备 dist，Forge 打包自带的下载不代替此独立比对基准。
- 包检查：设置 WINDCHIME_VERIFY_7ZIP 指向已核验的完整 7z.exe，执行 node scripts/verify-package.cjs，参数为 build-info.json 中的 stage。
- 暂存检查：node scripts/verify-installer-stage.cjs，参数为 build-info.json 中的 stage。

共享库测试和 pack:check 在本轮较早时已完成，业务代码随后没有变化，不重复把相同检查写成新执行。暂存测试只运行隔离的静默解包引擎，不执行公开安装器、不写注册表或快捷方式。
